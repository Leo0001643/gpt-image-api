# GPT Image API · 生产部署手册

> 适用环境：Ubuntu 22.04 / 24.04 · x86_64 · 纯 IP 访问 · HTTP 模式  
> 部署方式：Docker Compose 单机  
> 最后更新：2026-05

---

## 一、服务器最低配置

| 资源 | 最低 | 推荐 |
|------|------|------|
| CPU  | 2 核 | 4 核 |
| 内存 | 4 GB | **8 GB**（MySQL innodb_buffer=2G + 4 个服务各 1G）|
| 磁盘 | 40 GB SSD | 80 GB（图片/视频存储）|
| 系统 | Ubuntu 22.04+ | Ubuntu 24.04 ✅ |

---

## 二、服务器初始化

```bash
# 更新系统
sudo apt update && sudo apt upgrade -y

# 安装基础工具
sudo apt install -y curl git vim ufw

# 设置时区（与容器 TZ=Asia/Shanghai 保持一致）
sudo timedatectl set-timezone Asia/Shanghai
```

---

## 三、安装 Docker

```bash
# 官方一键安装脚本（支持 Ubuntu 24.04）
curl -fsSL https://get.docker.com | sudo sh

# 将当前用户加入 docker 组，免 sudo 执行
sudo usermod -aG docker $USER
newgrp docker

# 验证安装
docker --version          # Docker 26.x+
docker compose version    # Docker Compose v2.x+
```

---

## 四、配置防火墙

```bash
sudo ufw enable

sudo ufw allow 22/tcp     # SSH（必须保留，否则失去连接）
sudo ufw allow 17080/tcp  # 用户端 Web
sudo ufw allow 17088/tcp  # Admin 后台
sudo ufw allow 17200/tcp  # OpenAI 兼容 API

# MySQL(13306) 和 Redis(16379) 绑定在 127.0.0.1，不对外暴露
# 远程连接数据库请用 SSH 隧道（见第九步）

sudo ufw status
```

## 六、配置环境变量

```bash
cd /opt/gpt-image-api/deploy

# 从模板复制
cp env/.env.example env/.env.local

# 编辑配置（全部必填项见下方说明）
vim env/.env.local
```

### `.env.local` 填写说明

```bash
GIA_ENV=prod

# ── 对外端口（默认无需改）──────────────────────────
GIA_USER_WEB_PORT=17080
GIA_ADMIN_WEB_PORT=17088
GIA_OPENAI_PORT=17200

# ── MySQL ──────────────────────────────────────────
GIA_MYSQL_PORT=13306
GIA_MYSQL_ROOT_PASSWORD=【强密码，至少16位，含大小写+数字+符号】
GIA_MYSQL_DB=gpt_image_api
GIA_MYSQL_USER=gia
GIA_MYSQL_PASSWORD=【强密码，至少16位】
# 注意：密码与上面 GIA_MYSQL_PASSWORD 保持一致
GIA_DB_DSN=gia:【同上密码】@tcp(mysql:3306)/gpt_image_api?charset=utf8mb4&parseTime=True&loc=Local

# ── 远程运维账号（DML 权限，用于 Navicat/DBeaver 远程连接）──
GIA_DB_OPS_USER=giaops
GIA_DB_OPS_PASSWORD=【强密码，至少12位】

# ── Redis ──────────────────────────────────────────
GIA_REDIS_PORT=16379
GIA_REDIS_ADDR=redis:6379
GIA_REDIS_PASSWORD=【可为空，建议生产设置】

# ── 安全密钥（三个值必须各不相同）────────────────────
# 执行命令生成：openssl rand -hex 32
GIA_JWT_SECRET=【openssl rand -hex 32 的输出】
GIA_JWT_REFRESH_SECRET=【openssl rand -hex 32 的输出，与上不同】
GIA_AES_KEY=【openssl rand -hex 32 的输出，与上不同】
# ⚠️ AES_KEY 一旦设定、数据库中有加密数据后绝对不能修改！

# ── AI Provider ────────────────────────────────────
GIA_OPENAI_BASE=https://api.openai.com
GIA_GROK_BASE=https://api.x.ai

# ── 跨域（填服务器真实公网 IP）────────────────────
GIA_CORS_ORIGINS=http://【服务器IP】:17080,http://【服务器IP】:17088

# ── 日志 ───────────────────────────────────────────
GIA_LOG_DIR=/app/logs
```

### 快速生成三个安全密钥

```bash
echo "GIA_JWT_SECRET=$(openssl rand -hex 32)"
echo "GIA_JWT_REFRESH_SECRET=$(openssl rand -hex 32)"
echo "GIA_AES_KEY=$(openssl rand -hex 32)"
# 将输出的三行复制填入 .env.local
```

## 七、构建镜像并启动

```bash
cd /opt/gpt-image-api/deploy

# 构建所有镜像（首次约 5~10 分钟）
docker compose --env-file ./env/.env.local build --no-cache

# 后台启动全部服务
docker compose --env-file ./env/.env.local up -d

# 观察启动进度
docker compose --env-file ./env/.env.local ps
```

**预期所有服务状态：**

```
NAME            STATUS           PORTS
gia-mysql       healthy          127.0.0.1:13306->3306/tcp
gia-redis       healthy          127.0.0.1:16379->6379/tcp
gia-api         healthy
gia-admin       running
gia-openai      running
gia-worker      running
gia-user-web    running
gia-admin-web   running
gia-nginx       running          0.0.0.0:17080->17080/tcp, ...
```

> MySQL 首次启动会自动执行 Goose 数据库迁移和远程运维账号创建，需等待约 1~2 分钟。

## 九、远程连接数据库

MySQL 端口绑定在 `127.0.0.1`，通过 **SSH 隧道**安全访问，无需暴露端口到公网：

```bash
# 在你的本地电脑（Mac/Linux）执行
ssh -L 13307:127.0.0.1:13306 root@服务器IP -N
# 保持该终端运行
```

然后用 Navicat / DBeaver / TablePlus 等工具连接：

| 参数 | 值 |
|------|----|
| 主机 | `127.0.0.1` |
| 端口 | `13307`（本地转发端口）|
| 用户名 | `giaops` |
| 密码 | `GIA_DB_OPS_PASSWORD` 的值 |
| 数据库 | `gpt_image_api` |

> `giaops` 账号仅有 SELECT / INSERT / UPDATE / DELETE 权限，无法执行 DDL（DROP / ALTER / CREATE），保护表结构安全。

## 十、常用运维命令

```bash
cd /opt/gpt-image-api/deploy

# 查看所有容器状态
docker compose --env-file ./env/.env.local ps

# 实时查看日志
docker logs -f gia-api       # 用户 API
docker logs -f gia-admin     # Admin API
docker logs -f gia-openai    # OpenAI 兼容 API
docker logs -f gia-worker    # 后台 Worker
docker logs -f gia-mysql     # 数据库（含迁移日志）

# 重启单个服务
docker compose --env-file ./env/.env.local restart api

# 更新代码后重新部署
git pull
docker compose --env-file ./env/.env.local build api admin openai worker user-web admin-web
docker compose --env-file ./env/.env.local up -d

# 停止所有服务（数据 volume 保留）
docker compose --env-file ./env/.env.local down

# ⚠️ 彻底清除含数据（不可恢复）
docker compose --env-file ./env/.env.local down -v
```

## 十一、数据备份

```bash
# 手动备份 MySQL
docker exec gia-mysql mysqldump \
  -uroot -p【GIA_MYSQL_ROOT_PASSWORD】 \
  --single-transaction gpt_image_api \
  > /opt/backup/gpt_image_api_$(date +%Y%m%d_%H%M%S).sql

crontab -e

```

## 十二、注意事项

| # | 风险点 | 处理方式 |
|---|--------|----------|
| 1 | `GIA_AES_KEY` 一旦设定不可更改 | 记录到安全的地方（密码管理器），丢失或修改会导致所有账号凭证无法解密 |
| 2 | 默认管理员 `admin/admin123` | **首次登录后立即修改密码** |
| 3 | `.env.local` 含所有密钥 | 不要 `git commit` 该文件，已在 `.gitignore` 中排除 |
| 4 | MySQL 首次启动慢 | 等待 1~2 分钟，用 `docker logs -f gia-mysql` 观察迁移进度 |
| 5 | 内存不足 4G | 将 `innodb-buffer-pool-size=2G` 改为 `512M`（修改 `docker-compose.yml`）|
| 6 | 图片/视频数据 | 已挂载 `gia-storage` volume，容器重建不丢失 |
| 7 | `--env-file` 不能省略 | 每次 `docker compose` 命令必须带 `--env-file ./env/.env.local` |
